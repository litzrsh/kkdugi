# ADR-0002: 배치 편집과 계층형 관리 목록

> 2026-09-16: API 계약과 실제 퍼블리싱 구조는 [ADR-0006](0006-admin-api-contract-and-publishing.md) 및 계획 06의 현재 상태를 우선합니다. 아래 내용은 최초 설계 기록입니다.

- 날짜: 2026-09-15
- 상태: 설계 채택; 기본 메뉴 보호의 세부 범위는 제안

## 배경

공통코드·메시지·메뉴는 등록/수정/삭제를 한 번에 저장해야 한다. 코드 계층은 레벨별 조회, 메뉴 계층은 접기·펼치기 없는 트리다. ‘기본 불변 메뉴’와 ‘메뉴 삭제’ 요구를 함께 만족해야 한다.

## 결정

- 변경 상태는 정상/추가/수정/삭제예정/오류로 표현한다. 저장 버튼은 페이지의 전체 변경을 저장한다. 선택 행에만 저장되는 것으로 오해시키지 않는다.
- 추가 후 삭제는 변경 집합에서 제거한다. 기존 행 삭제는 삭제예정으로 유지하고 복원할 수 있다. 수정 후 삭제는 최종 DELETE 하나로 정규화한다.
- 기존 저장 ADR-0007에 맞춰 코드·메시지·메뉴는 전체 성공 또는 전체 롤백을 목표로 한다. 메시지 외 API는 아직 계약 제안이다.
- 검색·페이지·코드 레벨·메뉴·로케일 이동 전에 변경이 있으면 ‘저장 후 이동 / 변경 버리고 이동 / 계속 편집’을 제공한다. 저장 실패 시 이동하지 않는다. 페이지 간 변경 누적은 초기 버전에서 지원하지 않는다.
- 공통코드는 현재 부모의 직접 자식만 표시하고 breadcrumb·상위 이동·하위 목록 버튼으로 탐색한다.
- 메뉴는 평탄화한 preorder 데이터에 depth 들여쓰기·부모 경로를 표시한다. 펼침·접힘은 없다. 계층을 깨는 임의 열 정렬은 비활성화하며 형제 순서로 배치한다.
- Enterprise Tree Data를 필수 조건으로 두지 않는다. 제공된 AG Grid의 기능·라이선스를 확인한 뒤 기본 그리드 + 자체 계층 표현으로 구현한다.
- 메뉴 삭제예정은 서버가 확인한 전체 자손을 포함한다. 검색 결과에 보이지 않는 자손도 대상이며 확인창에 총 건수·대상 경로를 표시한다. 하위가 추가된 동시 변경은 저장 시 서버가 재검증해야 한다.
- 기본 메뉴는 코드·유형·부모 관계·기본 노출을 보호하는 것으로 제안한다. 로케일 라벨·설명은 편집 가능하게 한다. 기본 메뉴를 포함하는 조상 삭제도 금지한다. 사용자 정의 메뉴에 일반 삭제·하위 일괄 삭제를 적용한다.

## 결과와 한계

UI 잠금은 권한·불변성 검증의 대체가 아니다. 서버에서도 보호해야 한다. 기존 메시지 저장은 last-write-wins이며 낙관적 잠금이 구현됐다고 가정하지 않는다. 다른 관리 API의 충돌 응답은 후속 계약에서 정한다.

응답 유실로 저장 결과를 모르는 경우 자동 재전송하지 않고 재조회·대조를 안내한다. 저장 중 중복 클릭을 막고, 오류 시 입력값과 변경분을 유지한다.

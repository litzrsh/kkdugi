# 모바일 디자인 및 조작 기준

- 날짜: 2026-09-15 / 상태: 기획 기준, 구현·실기 검증 미착수
- 확정 방향: 데스크톱과 모바일을 함께 설계한다. Kluvo는 연동 구조만 참고하고 디자인은 kkdugi 전용으로 만든다.
- 관련: [통합 Vue Dialog](../adr/0005-unified-vue-dialog-responsive.md), [공통 디자인](02-design-publishing-guide.md)

## 1. 적용 범위와 크기

다섯 관리 화면 모두 모바일에서 검색·상세 확인·등록된 필수 작업을 수행할 수 있어야 한다. 모바일을 단순 축소 미리보기로 취급하지 않는다. 데이터 모델·배치 변경 집합·검증·권한 규칙은 화면 폭에 따라 바꾸지 않는다.

| 폭 | 탐색 / 레이아웃 | 편집·매핑 dialog |
|---|---|---|
| 1024px 이상 | 고정 sidebar, 본문 24px, 다열 검색 | 중앙 560/880px 기본 |
| 768~1023px | drawer 탐색, 본문 20px, 검색 2열 | 여백 16px 이상, 가용 폭 내 중앙 |
| 768px 미만 | drawer 탐색, 본문 16px, 검색 1열 | 전체 화면, 모서리 0, safe-area 대응 |

위 경계는 제안 토큰이며 Bulma 기본 breakpoint와의 적용 범위를 구현 시 명시한다. 320px 폭까지 핵심 조작을 확인하고 주 검수는 360/390/768/1024/1440px이다. 가로 회전·확대·키보드 개방은 별도로 확인한다.

## 2. 공통 모바일 shell

- header는 메뉴 버튼·현재 화면명·계정 메뉴 중심으로 구성한다. 긴 제목은 본문에서 전체 표시한다. 로케일 선택은 계정 메뉴에서 접근 가능하게 한다.
- drawer에는 동일 5개 메뉴를 제공하고 선택 후 닫는다. 배경은 비활성화하고 초점을 관리한다. drawer와 업무 dialog를 동시에 조작하게 하지 않는다.
- 검색은 기본 펼침, 조회 후 사용자가 접을 수 있다. 접은 상태에 현재 조건 요약·필터 건수·검색 버튼을 남긴다. 조건 변경 후 검색 전이라는 상태를 표시한다.
- 본문·입력 16px 기본, 설명 14px 제안. 버튼·아이콘 버튼·체크박스 라벨의 터치 영역은 최소 44×44px, 인접 위험 동작은 충분히 떨어뜨린다. 실제 아이콘 그림은 더 작아도 된다.
- 우측 행 버튼을 여러 개 촘촘하게 넣지 않는다. ‘행 작업’ 버튼으로 명시적 액션 목록을 열고 선택한 사용자/코드 식별자를 제목에 표시한다. hover나 더블클릭을 필수 입력 방식으로 사용하지 않는다.
- 하단 배치 바: 변경 건수·저장을 우선 표시하고 변경 취소는 식별 가능한 보조 버튼으로 제공한다. 저장이 현재 행만 대상인 것으로 오해되지 않게 ‘전체 변경 저장’ 설명을 둔다.
- 일반 페이지에서 높이 320px 그리드 제안은 목표치다. 작은 가로 화면·키보드 환경에서는 화면 높이를 침범하는 강제 min-height로 사용하지 않는다.

## 3. AG Grid와 모바일 편집

- AG Grid를 유지한다. 그리드 영역 안에서 가로 스크롤하며 페이지 전체에 가로 스크롤이 생기지 않게 한다. 열을 강제로 압축해 글자를 읽기 어렵게 만들지 않는다.
- 좁은 화면에서는 넓은 식별 열 고정을 해제해 데이터 영역을 확보한다. 필요 시 작은 선택 열만 고정한다. 현재 행 식별은 행 상세 제목으로 보완한다.
- 행 높이 48px 이상 제안, 체크박스는 셀 전체 라벨 영역으로 선택할 수 있게 한다. 터치 스크롤과 행 선택이 충돌하지 않는지 검증한다.
- ‘행 편집’ 동작은 전체 화면 Vue 폼을 연다. 배치 화면에서 이 폼의 적용은 동일 변경 집합만 갱신하며 서버에 즉시 저장하지 않는다. 취소는 해당 폼 진입 시 값으로 복원한다.
- 데스크톱 inline 편집과 모바일 폼이 validation·change store를 공유한다. 회전·창 크기 변경으로 모드를 바꿔도 현재 editor 값을 먼저 초안에 반영하고 입력을 잃지 않는다. 컴포넌트를 재마운트하지 않는 presentation 변경을 우선한다.
- 현재 페이지 선택 범위·서버 페이징은 유지한다. 페이지 이동은 이전/다음·현재/전체 페이지를 우선하고 크기 선택은 보조 설정에 둘 수 있다.
- 모든 필드에 접근 가능해야 한다. 요약 표시에서 숨긴 항목은 행 상세/편집에서 제공하며 임의로 기능을 제거하지 않는다.

## 4. 화면별 모바일 행동

| 화면 | 모바일 설계 |
|---|---|
| admcode | breadcrumb 중간 경로 축약 + 전체 경로 보기, 상위/하위 버튼 유지. 선택 행의 코드·코드명·설명 등은 전체 화면 편집으로 제공. 삭제예정·복원·하위 존재 차단 유지 |
| admmsge | 코드별 한 행과 등록 언어별 열을 유지하고 가로 스크롤. ‘번역 편집’에서 같은 행의 모든 등록 언어를 세로 필드로 편집. 코드·미등록·번역 삭제를 분리, 언어 검색으로 이동해도 숨은 값 유지. 적용 후 배치 저장 |
| admmenu | 접기·펼치기 없는 전체 트리 유지. 과도한 depth 들여쓰기를 제한하고 전체 부모 경로를 상세에 표시. 로케일 라벨·설명은 세로 편집. 하위 포함 삭제 범위·기본 보호 안내를 전체 화면에서도 유지 |
| admauth | 권한 기본 목록과 메뉴/사용자 버튼 접근 유지. 매핑은 전체 화면, 검색 상단·선택 요약·저장 하단. 다중 페이지 기존 선택 유지, 메뉴 부분선택 표현 |
| aduser | 사용자 식별·상태를 먼저 확인하고 행 작업에서 권한·수정·비밀번호 초기화·영구 삭제 접근. 다중 선택 후 상태 일괄 변경, 위험 실행은 ID/이름/건수 확인. 가로 스와이프만으로 삭제하지 않음 |

메시지 언어 편집은 별도 메시지 Dialog 구현이 아니라 공통 DialogHost의 본문 SFC다. 다국어 값이 많아도 한 언어를 수정할 때 다른 언어 초안을 잃지 않는다.

## 5. 공통 dialog 반응형

```text
모바일 업무 편집
┌ 화면/대상 제목                       닫기 ┐
│ 대상 코드 · 미저장 상태                  │
│ 오류 요약 (있을 때)                      │
│ 레이블                                  │
│ 입력                                    │
│ … 스크롤 가능한 폼 …                    │
├ 취소                         변경 적용 ──┤
└ safe-area                               ┘
```

- 짧은 alert/confirm은 좌우 16px 여백 내 중앙 배치한다. 장문은 본문 스크롤·제목/동작 고정. 버튼 문구가 길면 세로로 배치하되 DOM과 시각 순서를 맞춘다.
- 업무 편집·매핑은 모바일에서 전체 화면. 같은 모델과 Vue 본문을 유지하고 크기만 바꾼다. 화면 회전으로 dialog 결과·초안이 초기화되어서는 안 된다.
- 높이는 가용 viewport 기준으로 계산하고 `100dvh`·safe-area를 고려한다. 가상 키보드 대응은 이 값만으로 완료됐다고 보지 않고 실제 브라우저에서 visual viewport를 확인한다.
- 키보드가 입력·오류·적용 버튼을 가리면 폼 스크롤과 가용 높이를 조정한다. 고정 footer가 콘텐츠를 가리거나 스크롤을 막지 않게 한다. dialog 내부 스크롤을 우선하고 배경 스크롤은 잠근다.
- 초점은 제목/안내로 시작할 수 있게 하며 사용자가 입력을 터치할 때 키보드를 연다. 오류 제출 후 첫 오류 필드로 이동한다.
- 앱 내부 뒤로가기와 dialog 닫기는 같은 dirty 가드를 사용한다. 브라우저/OS 뒤로가기를 무조건 가로채지는 않는다. 초기 버전은 명시적 닫기와 페이지 이탈 경고를 보장하고, history 연동은 별도 설계 없이 추가하지 않는다.

## 6. 모바일 인수 시나리오

1. 320/360/390px에서 메뉴→검색→행 선택→편집→적용→배치 저장 완료. 페이지 전체의 가로 넘침 없음(그리드 내부 가로 스크롤은 허용).
2. 터치만으로 모든 필수 행동 수행. 더블클릭·hover·작은 아이콘 의존 없음. 행 스크롤 중 오작동 없음.
3. 모바일 세로·가로 전환, 키보드 열림/닫힘, 200% 확대에서 입력과 주요 동작 접근 가능.
4. 긴 영어 라벨·한글 장문·5개 이상 언어·긴 코드경로·다수 메뉴 depth에서 잘림 없이 전체 내용 접근 가능.
5. alert·confirm·편집·매핑이 공통 Vue shell을 사용하고 화면 폭 변경 시 입력·오류·선택 보존.
6. 팝업 취소/저장 실패/저장 중 owner 종료/로딩 실패에서 Promise·초점·배경 스크롤 잠금이 남지 않음.
7. iOS Safari·Android Chrome 실제 기기 또는 해당 엔진 환경에서 키보드·viewport·native dialog·터치를 확인. 데스크톱 폭 축소만으로 모바일 검수 완료 처리하지 않음.

이번 문서에는 설계 목표만 기록했다. 브라우저별 지원·성능·접근성 통과 결과는 구현 후 검증표에 작성한다.

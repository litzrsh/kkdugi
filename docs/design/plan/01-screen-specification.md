# 관리자 화면 기획 명세

> 2026-09-16: API 계약과 실제 퍼블리싱 구조는 [ADR-0006](../adr/0006-admin-api-contract-and-publishing.md) 및 계획 06의 현재 상태를 우선합니다. 아래 내용은 최초 설계 기록입니다.

- 날짜: 2026-09-15 / 상태: 후속 구현용 설계 초안
- 표의 코드·메뉴·사용자 요구 동작은 확정. 필드 상세·정책은 제안이며 DB/API와 최종 매핑한다.
- 모든 화면의 모바일 행동은 [모바일 조작 기준](05-mobile-interaction-specification.md)을 따른다. 모든 안내·확인·편집 팝업은 [통합 Vue Dialog](../adr/0005-unified-vue-dialog-responsive.md)로 구현할 계획이다.

## 1. 정보 구조

| lv1 | lv2 | 코드 | 유형 | 기본 노출 |
|---|---|---|---|---|
| 시스템관리 | — | — | 그룹 | Y |
| 시스템관리 | 공통코드관리 | admcode | 화면 | Y |
| 시스템관리 | 메시지관리 | admmsge | 화면 | Y |
| 시스템관리 | 메뉴관리 | admmenu | 화면 | Y |
| 시스템관리 | 권한관리 | admauth | 화면 | Y |
| 시스템관리 | 사용자관리 | aduser | 화면 | Y |

원본 표의 메뉴관리 행 열 정렬은 위와 같이 정규화했다. 사용자 코드 `aduser`를 다른 이름으로 교정하지 않는다. 기본 노출 Y와 사용자 접근 권한은 별개다. 접근 가능한 메뉴만 탐색에 제공하되 서버에서도 권한을 검사한다.

## 2. 공통 화면 구성

```text
┌ kkdugi / Admin ────────────── 로케일 · 현재 사용자 ┐
│ 시스템관리      │ 시스템관리 / 현재 화면           │
│ 공통코드관리    │ 제목 + 한 줄 설명                │
│ 메시지관리      │ 검색 조건 / 초기화 / 검색         │
│ 메뉴관리        │ 목록 건수    행 추가 / 선택 삭제  │
│ 권한관리        │ 체크 · 상태 · 데이터 · 행 작업    │
│ 사용자관리      │ AG Grid                          │
│                 │ 건수 / 페이지 크기 / 페이지 이동 │
│                 │ 변경 요약 / 변경 취소 / 저장     │
└─────────────────────────────────────────────────┘
```

- 과업과 무관한 대시보드 카드·차트는 배치하지 않는다.
- 검색은 Enter 또는 검색 버튼으로 실행하고 1페이지로 이동한다. 초기화는 조건만 지우며 검색은 별도로 실행한다.
- 목록 선택은 현재 페이지로 제한하고 상단 체크도 현재 페이지 대상임을 표시한다. 이동 시 선택을 초기화한다. 검색 결과 전체 선택은 초기 범위 밖이다.
- 페이징 제안: 기본 20, 선택 20/50/100. UI 페이지는 1부터, API 페이지와 변환한다. 총건수는 필터 결과다. 메뉴는 전체 계층 목록으로 페이지를 나누지 않는다.
- Grid 기본 편집은 더블클릭/F2/Enter 진입, Tab 이동, Esc 편집 취소. 실제 키 동작은 선택한 AG Grid 버전에서 검증한다. 수정 가능 셀과 읽기 전용 셀을 구별한다.
- 배치 변경 시 추가 N·수정 N·삭제 N을 하단에 표시한다. 저장은 전체 변경 대상. 삭제는 개수·대상을 확인한 뒤 삭제예정 처리한다. 변경 취소는 최초 조회 상태로 복구한다.
- 화면 이동 시 변경 보호는 ADR-0002를 따른다. 저장 성공 후 삭제된 마지막 행 때문에 페이지가 비면 직전 유효 페이지를 조회한다.

## 3. admcode / 공통코드관리

**목적:** 계층별 코드를 탐색하고 현재 레벨을 일괄 편집한다.

- 검색: 코드경로, 코드, 코드명. 부모 경로 선택 후 해당 레벨을 조회한다. 코드·코드명은 현재 부모의 직접 자식 대상 부분검색으로 제안한다.
- 상단 경로: 전체 / 상위 코드명 / 현재 부모. ‘상위 목록’과 행별 ‘하위 목록 (N)’ 제공. 루트에서는 상위 이동 비활성화.
- 열: 선택, 변경 상태, 코드, 코드명, 설명, 사용 여부, 정렬순서, 하위 건수, 하위 목록. 부모 경로는 상단과 읽기 전용 정보에 표시한다.
- 행 추가: 현재 부모를 자동 지정. 코드 필수·부모 내 중복 금지 제안, 코드명 필수. 실제 키 범위·길이는 DB 계약 확인 후 고정한다.
- 기존 코드·부모는 편집 불가 제안. 계층 이동/코드 변경은 별도 기능으로 남긴다.
- 등록·수정·삭제는 배치 저장. 하위 코드가 있는 코드 삭제는 초기 제안상 차단하고 하위를 먼저 정리하도록 안내한다. 메뉴의 cascade 삭제 규칙을 코드에 자동 적용하지 않는다.
- 빈 목록: ‘현재 경로에 코드가 없습니다’와 추가 버튼. 검색 결과 없음은 조건 초기화 안내.
- 완료 시나리오: 루트→하위→상위 탐색, 혼합 CRUD, 중복 오류, 하위 존재 삭제 차단, 레벨 이동 변경 보호.

## 4. admmsge / 메시지관리

**목적:** 동일 메시지의 모든 등록 언어 값을 한 행에서 비교·편집한다.

- 검색: 메시지 코드, 메시지 내용. 그룹·유형 별도 필터는 확장 제안. 내용 검색은 등록 언어 전체에서 검색한다.
- 열: 선택, 변경 상태, 메시지 코드(고정), 등록 언어별 메시지, 수정일시(계약이 제공할 때). 언어 열은 시스템 등록 순서, 코드별 페이징.
- 코드 아래 형식 안내와 예시를 제공하고 위반 셀에 사유를 표시한다. 세부 규칙·현재 백엔드와의 차이는 ADR-0003 참조.
- 장문 셀은 축약 표시하되 키보드로 열 수 있는 큰 텍스트 편집 팝업에서 전체 값을 편집한다. 줄바꿈·`{0}` 등의 인자를 보존한다.
- 신규 행은 코드와 적어도 하나의 언어 값 필요 제안. 미등록 번역은 ‘미등록’으로 구분한다. 기존 번역 삭제는 별도 셀 동작이며 코드 행 삭제와 구별한다.
- 행 추가/선택 삭제/전체 변경 취소/저장. 저장 오류는 코드·언어별 셀에 연결하고 첫 오류로 이동한다.
- 완료 시나리오: 3개 이상 언어, 코드별 2페이지 이상, 언어값 추가·수정·삭제 혼합, 전체 코드 삭제, flat 요청 오류 매핑, 공백·대문자·개행·잘못된 구간 거부.

## 5. admmenu / 메뉴관리

**목적:** 메뉴 계층 및 로케일별 라벨·설명을 한 목록에서 관리한다.

- 검색 제안: 메뉴 코드·라벨. 결과는 일치 노드와 조상 경로를 함께 표시한다. 비일치 조상은 경로 문맥임을 표시한다.
- 열: 변경 상태, 계층 메뉴명, 메뉴 코드, 유형(그룹/화면), 노출 여부, 형제 정렬순서, 기본 메뉴 표시, 하위 추가, 수정, 삭제.
- 접기·펼치기 없이 전체 트리 노출. depth는 들여쓰기와 경로로 표시한다. 부모보다 자식이 먼저 나타나지 않는다.
- 추가 팝업: 부모, 코드, 유형, 노출, 순서, 화면 경로(화면 유형만), 로케일별 라벨·설명. 코드 중복·자기 자신/자손 부모 지정·순환 금지. 경로 형식은 서버 정책과 확정한다.
- 수정 팝업: 기본 정보 + 등록 언어별 라벨·설명. ‘변경 적용’은 화면의 미저장 변경에만 반영한다. 최종 ‘저장’에서 배치 전송한다. 취소는 팝업 진입 시점으로 복구한다.
- 삭제: 대상과 모든 자손을 삭제예정 처리. 현재 검색으로 보이지 않는 자손 포함 건수 확인. 복원은 이 삭제 작업이 만든 자손 삭제예정만 함께 복원하고 기존 별도 편집 상태를 보존한다.
- 기본 메뉴 보호는 ADR-0002의 제안에 따른다. 일반 메뉴 삭제는 최종 저장 시 실행된다.
- 완료 시나리오: 3레벨 이상, 펼침 버튼 없음, 언어별 팝업 변경 취소/적용, 숨은 자손 cascade, 기본 메뉴 보호, 순환 차단.

## 6. admauth / 권한관리

**목적:** 권한과 메뉴·사용자 매핑을 관리한다.

- 검색 제안: 권한 코드, 권한명. 열: 코드, 권한명, 설명, 메뉴 버튼, 사용자 버튼. 메뉴/사용자 수는 API 제공 시에만 표시한다.
- 권한 기본정보 등록·수정·삭제의 저장 방식은 사용자 요구에 명시되지 않았다. 그리드 배치 편집을 제안하되 확정 항목으로 남긴다.
- 메뉴 팝업: 대상 권한 식별, 전체 계층 메뉴, 현재 매핑 체크 상태, 검색. 그룹 체크는 하위 매핑 일괄 선택 제안. 검색 때문에 숨겨진 항목의 기존 선택을 잃지 않는다. 부분 선택은 별도 표시한다.
- 사용자 팝업: 사용자 검색·선택·현재 매핑, 페이징. 다른 페이지의 기존 매핑 유지, 추가/제거 diff만 저장하는 계약을 사용한다.
- 매핑 팝업은 ‘매핑 저장’으로 독립 저장하는 제안. 저장 전 변경 요약, 실패 시 선택 보존. 메인 권한이 미저장 신규이면 매핑 버튼 비활성화한다.
- 삭제 시 사용 중 권한·마지막 관리자 권한 처리, 메뉴 권한의 CRUD 세분화/접근 단위는 서버 정책 미확정이다. 임의로 허용하지 않는다.
- 완료 시나리오: 기존 매핑 복원, 메뉴 부분선택, 사용자 페이지 이동 후 선택 보존, 저장 실패, 권한 없는 조작 거부.

## 7. aduser / 사용자관리

**목적:** 사용자 기본정보·권한·상태·비밀번호 초기화를 관리한다.

- 검색 제안: 사용자 ID, 이름, 상태. 열: 선택, 사용자 ID, 이름, 이메일(스키마 확인), 상태, 권한, 비밀번호 초기화, 수정, 삭제.
- 기본정보 수정 팝업: 사용자 ID 읽기 전용, 이름·이메일 등 서버가 허용하는 필드. 저장 시 해당 사용자만 즉시 반영하는 제안. 필수값·길이·고유성은 서버 규칙으로 확정한다.
- 권한 팝업: 전체 권한 목록과 사용자에게 매핑된 체크 상태, 추가/제거 저장. admauth 사용자 매핑과 동일 관계를 편집한다.
- 비밀번호 초기화: 대상 ID·이름과 실행 영향을 확인한 뒤 요청. 임시 비밀번호 표시/메일 발송/재설정 링크 중 어떤 방식인지 아직 미정. 성공 전 완료 메시지를 표시하지 않는다.
- 영구 삭제: 대상 ID·이름과 복구 불가를 명시해 확인 후 즉시 삭제하는 제안. 실패하면 행을 유지한다. 연관 프로젝트·이력·계정 소유 데이터 처리는 백엔드 정책 의존이다.
- 상태 일괄 변경: 선택 건수→대상 상태 선택→변경 전후 요약→실행. 상태 목록은 서버 공통코드 사용, 임의 enum을 확정하지 않는다. 초기 제안은 전체 성공/전체 실패; 부분 성공 계약이면 성공·실패를 분리 표시한다.
- 사용자 신규 등록은 원문에 없으므로 이번 필수 범위에 넣지 않는다. 자기 계정 삭제·자기 상태 변경·마지막 관리자 제거 정책은 구현 전 확인한다.
- 완료 시나리오: 수정 취소/저장, 권한 매핑, 초기화 취소/실패/성공, 영구 삭제 확인, 선택 0건/다중 상태 변경, 서버 거부 시 데이터 유지.

## 8. 공통 상태·팝업

| 상태 | 표시·행동 |
|---|---|
| 최초 로딩 | 목록 로딩 영역, 중복 조회 방지, aria-busy |
| 빈 데이터 | 비어 있는 이유와 가능한 다음 행동 |
| 조회 실패 | 오류 설명과 재시도; 기존 데이터가 남으면 이전 결과임을 표시 |
| 저장 중 | 진행 표시, 저장·이동 중복 방지 |
| 검증 오류 | 상단 요약 + 필드/셀 오류, 입력 보존 |
| 저장 실패 | 변경분 유지, 재시도 가능 여부 안내 |
| 세션 만료/권한 없음 | 서버 상태에 맞는 안내, 입력을 민감한 브라우저 영구 저장소에 자동 저장하지 않음 |
| 성공 | 처리 건수 안내, 변경 표시 초기화, 갱신된 목록 |

팝업은 제목·설명·본문·취소/주요 동작 순서. 모달 진입 시 초점 이동, Tab 순환, 닫힐 때 호출 버튼으로 복원한다. 미저장 값이 있는 Esc/닫기는 버림 확인을 거친다. 위험 동작은 취소에 초기 초점을 둔다. 배경 클릭으로 편집 내용을 잃지 않게 한다.

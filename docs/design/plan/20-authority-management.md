# 권한관리 화면 구현

## 범위

- Pragma: templates/pragma/admin/authority.vue → static/vue/pages/AuthorityPage.vue.
- docs/api/authority.md의 현행 API 7개를 사용한다. 권한 코드·유형·이름 검색, 페이징, 등록·수정·삭제, 메뉴·사용자 연결을 지원한다.
- 행별 저장 방식이며 공통 배치 저장 막대는 두지 않는다. 기존 AG Grid/공통 Vue Dialog와 라이트 테마를 사용한다. 상태와 작업은 중앙 정렬한다.
- 기본 정보 팝업: 코드·유형(ROLE/PLAN)·이름·사용 여부·설명. 이름과 설명은 현행 API의 단일 문자열이다.
- 메뉴 팝업: 트리를 전부 펼치고 조회/쓰기/삭제/실행 4개 RBAC 열을 맞춘다. 숫자 키 10/20/30/40을 그대로 사용한다. 프로그램 없는 그룹은 체크박스가 없고, 검색해도 일치 메뉴의 조상을 유지한다.
- 사용자 팝업: 사용자 + 시작일 ~ 종료일의 컴팩트한 행. 기존 연결은 상세 API의 이름·원형 프로필·ID를 표시하고 기간을 보존한다. 후보 검색 결과로 선택한 사용자나 기존 연결을 덮어쓰지 않는다.
- 전체 교체 API이므로 기본 정보 저장에는 users/menus를 생략한다. 각 연결 팝업은 자신이 관리하는 매핑만 전체 목록으로 보낸다. 빈 목록 저장은 일반 권한의 연결 해제다.
- SYS_ADMIN은 코드·유형·사용 여부·삭제를 잠근다. API 문서의 주의에 따라 기존 사용자 연결과 적용 기간도 보존하며 신규 사용자 추가는 허용한다.
- READ만 있으면 조회 팝업으로 표시한다. WRTE/DELT로 쓰기/삭제 버튼을 분리하고 모든 요청에 화면 메뉴 ID를 유지한다.
- 오류는 팝업 내 초안을 유지한다. 저장 성공 후 목록 재조회 실패는 저장을 재전송하지 않고 조회만 재시도한다. 팝업 종료·페이지 종료 시 비동기 응답과 요청을 정리한다.
- 모바일은 기존 전체 화면 폼 팝업과 내부 표 가로 스크롤을 사용한다. textarea는 고정 높이·크기 조절 불가다.

## API 제약

- 상세 API의 users.name/users.image를 표시하며, 이미지가 없거나 로드에 실패하면 기본 사용자 아이콘을 표시한다. 이름이 없으면 ID를 표시한다. 요청에는 ID와 적용 기간만 전송한다.
- 후보는 정상 상태·미연결 사용자 최대 200명이다. 검색어로 범위를 좁힌다.
- 변경된 접근 권한은 다음 로그인부터 적용된다. 마지막 관리자 보호는 백엔드 미구현이며 화면에서 기존 SYS_ADMIN 사용자 연결/기간 변경을 차단한다.

## 검증

- Maven 전체 테스트와 실제 Spring 렌더링 Pragma(READ, WRTE, DELT 조합) 검증.
- JS API 경로/헤더/페이로드, 매핑 전체 교체/보존, 숫자 RBAC, 그룹 제외, 날짜 및 SYS_ADMIN 보호 검증.
- 실제 정적 자산 및 Spring 렌더링 화면을 사용하는 브라우저 fixture에서 검색·CRUD·메뉴/사용자 연결·저장 오류·모바일·읽기 전용을 검증한다.

## 검증 결과 (2026-09-19)

- 서버 테스트 210개 통과. PragmaControllerTest에서 admin/authority를 실제 렌더링하고 권한 조합 1/3/5/15를 검증했다.
- JavaScript 테스트 42개 통과. 7개 권한 API의 메서드·경로·메뉴 헤더, 교체 매핑 보존, 날짜/그룹/SYS_ADMIN 보호 및 실제 렌더링 SFC 컴파일을 포함한다.
- Edge HTTP fixture에서 등록·수정·삭제, 검색·초기화·페이징, 409 저장 실패/재시도, 저장 후 목록 재조회 실패, 메뉴 트리 정렬, 사용자 후보 검색/기간, 읽기 전용·삭제 전용, 한국어/영어 및 모바일 팝업을 확인했다. 실제 사용자 권한은 변경하지 않았다.

## 화면 조정 (2026-09-19)

- 목록에서 설명 컬럼을 제거했다. 메뉴/사용자 버튼은 각 독립 중앙 정렬 컬럼에 배치하고 작업 컬럼은 수정/삭제만 표시한다.
- 등록/수정의 역할 코드는 select로 선택한다: ADMIN(관리자), USER(사용자), ANONYMOUS(손님). SYS_ADMIN(시스템관리자)은 기존 시스템 권한에서 잠긴 값으로만 표시하며 신규 생성/다른 권한에서 선택할 수 없다.
- 기존 비표준 역할은 수정 시 현재 값으로만 표시하고 유지할 수 있다. 새 선택지로 제공하지 않는다. API 전체 교체에서 기존 값을 조용히 변경하지 않도록 하기 위함이다.
- 설명 편집 필드는 등록/수정 팝업에 유지한다. ANONYMOUS는 역할 코드 선택지만 제공하며 비로그인 접근 동작은 변경하지 않는다.

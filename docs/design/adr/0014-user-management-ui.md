# ADR-0014 사용자관리 화면과 권한 연결

- 날짜: 2026-09-20
- 상태: 적용
- 근거: [사용자 API](../../api/user.md), [사용자 시스템 설계](../../user-system-design.md)

## 결정

1. 실제 kkdugi-admin에 UserPage.vue와 admin/user Pragma 조각을 추가한다. 공통 Grid/DialogHost 및 라이트 테마를 재사용하고 표시 문자열은 Spring message로 제공한다.
2. 사용자 기본 정보는 개별 즉시 저장, 선택 사용자 상태는 일괄 저장한다. 로그인 ID는 생성 이후 잠근다. 프로필 URL은 원형 미리보기와 로드 실패 대체 아이콘을 제공한다.
3. 사용자 권한은 기존 목록 대비 insert/update/delete 차이만 전송한다. 변경하지 않은 적용 기간과 연결은 전송하지 않는다. WRTE는 신규 연결·기간 수정, DELT는 기존 연결 해제를 허용한다.
4. 공통 다이얼로그에 selectionLocked/datesLocked를 추가하여 체크박스와 기간 입력을 독립적으로 잠근다. 기존 권한관리의 locked 동작도 유지한다.
5. 권한 후보 API는 사용자 도메인에 추가한다. 다른 메뉴의 X-Menu-Id를 대신 보내거나 권한관리 API의 인가 규칙을 완화하지 않는다.
6. 후보 검색 후에도 기존 연결과 선택 상태를 보존한다. 미사용 권한은 신규 후보에서 제외하되 기존 연결은 표시·편집할 수 있다.
7. 마지막 SYS_ADMIN 보호는 현재 사용자 백엔드의 의도된 정책을 따른다. 화면에 별도 삭제/기간 보호 규칙을 추가하지 않는다. 자기 자신 영구 삭제는 서버가 409로 거부한다.

## 사용자에게 전달할 현재 동작

- 등록/초기화 시 임시 비밀번호를 만들지만 자동 이메일 전달은 아직 없다. 완료 메시지가 발송 성공을 의미하지 않도록 한다.
- 상태 변경은 현재 로그인 차단이나 기존 세션 종료에 연결되지 않는다. 상태 변경 팝업에 이를 명시한다.
- 권한 변경은 다음 로그인부터 반영된다.

## 화면·오류 처리

모바일은 전체 화면 형태의 폼 팝업과 본문 스크롤을 사용한다. 목록/권한 테이블만 가로 스크롤한다.
상태·작업 컬럼은 중앙 정렬한다. textarea 높이는 고정이며 크기 조절을 금지한다.
저장 실패는 팝업 입력을 유지하고, 성공 후 재조회 실패는 저장을 반복하지 않고 목록 재시도를 안내한다.
페이지 전환 시 진행 중인 요청과 소유한 팝업을 정리한다.
